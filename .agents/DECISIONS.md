# 設計判断

変更履歴ではなく、決定と理由の記録。状態は 2 つに分ける。

- **実装済み**: コードとテストにある。
- **採用決定済み・未実装**: 方針は決まったが、コード・スキーマには無い。実装済みとして扱わず、現状の記述（`PROJECT.md`、`DATA.md`、`docs/`）も書き換えない。実装したら「実装済み」へ移す。

- **D-01. 公式忠実（Official-faithful）と leakage-safe（Research）を並行して持つ。** 公式忠実では、公式が test を validation・モデル選択に使うなら使う。ただし `selection_uses_test = true` を Dataset に計算して記録し、**独立した汎化性能として扱わない**。leakage-safe は train / valid / test が独立で、test を選択に使わない。評価用 DB（`resource.duckdb`）の「test を学習・検証に使わない」規則は**維持**し、例外は再現用 DB（`reproduction.duckdb`）と再現プロトコルの中だけに置く。例外を使うには、Dataset 側の `selection_uses_test` と学習設定の `data.allow_test_selection` の両方が要る。**関係**: #18（評価用セットと test の学習・検証への使用を拒否）は評価用 DB と Legacy 経路で有効のまま。矛盾しない。
- **D-02. 公式の実効動作を、欠陥も含めて再現する。** 公式との差は 4 つに分け、混ぜない: `official_effective`（公式の実効動作）、`minimal_launch_repair`（起動のための最小補修）、`algorithm_change`（結果を変える修正）、`research_improvement`（研究上の改良）。最初以外は別の Protocol（`parent_protocol_id` と `deviations`）として登録し、公式再現とは呼ばない。
- **D-03. MP-SENet は公式の 400 epoch、README の 2 GPU・global batch 4 を再現対象とする。** 段階的に実行する（実行は 30 分以上のジョブで、投入前に承認が要る）。**関係**: #15・#16（Global batch を厳密に保つ）と整合する。
- **D-04. MossFormerGAN は scratch 学習とする。** `T/train.sh` は既定で `init_checkpoint_path=…/last_best_checkpoint.pt` が存在すれば finetune として始まる（G の lr 1e-4）。scratch は初期 checkpoint を渡さない（公式では `init_checkpoint_path='None'` という**文字列**）。結果にこの開始条件を明記する。**関係**: #23（AdamW の weight decay 既定 0.01）は変えない。
- **D-05. SEMamba++ は公式 GitHub の固定 commit と、HEAD の `config.yaml` を再現対象とする。** 素材が公式と違う場合（手元の VCTK、別の雑音・RIR）は、公式素材の再現と**分け**、「公式プロトコル準拠・代替素材」と呼ぶ。「公式データセットの再現」と呼ばない。出荷状態で起動しない 4 点の最小補修は**許すが、今は実装しない**。必要になった時点で `minimal_launch_repair` の別 Protocol として決める。
- **D-06. DFN3 は公式素材を優先する。** `dataset.cfg`、DNS4、PTDB、RIR 集合が無い間は UNKNOWN / BLOCKED とし、公式素材の Dataset は `declared_status = blocked` にする。代替素材は別プロトコル準拠として別に登録し、「出荷モデルの学習データの再現」と呼ばない。**関係**: #27（DFN3 の公式学習は出荷 ini の batch schedule と 120 epoch）は変えない。オンライン混合の式は下記 42。公式素材の Dataset は blocked のまま。
- **D-07. TF-GridNet は ESPnet 公開 MS-SNSD SE recipe を再現対象とし、「ESPnet 公開 SE レシピの再現」と呼ぶ（論文の実験の再現ではない）。** 生成の seed、条件、出力マニフェストを記録する。公式は未シードで再現不能なので、audio-db が足す決定性は**文書化した差**（`deviations`）として残す。**関係**: #26（TF-GridNet の公式学習。**単一プロセスの chunk 分割**、VoiceBank を使う）は、MS-SNSD の事前生成と複数 rank の chunk 計画を足すことで拡張される。#26 と #31 の「best 5 は valid loss 最小と valid si_snr 最大」は、TARGETS が確認した実効（`si_snr` は stats に無く無効、実効は `valid.loss` のみ、TF-Locoformer は `ave_5best`）と食い違う。実装時に Trainer の選択規則を実効に合わせる。`valid.loss.ave_5best` は下記 40 で実装済み。有限な検証損失が `keep_nbest` 件未満のときは平均ファイルを書かず、`ave_1best` のリンクは下記 41。
- **D-08. TF-Locoformer の DNS データはオンデマンドの段階で扱う。** 現行の段階名は S0（条件の計画。WAV は作らない）、S1（メモリ上で公式の式と比べる。WAV は残さない）、S2（3000 h 相当の固定条件を DuckDB とスナップショットへ登録する）、S3（小さい Dataset で Trainer を通す）である。旧設計の S0〜S4（約 1.04 TB の事前生成 WAV）は履歴であり、現行の実装はそれを作らない。詳細は下記 40。**30 分以上の TSUBAME ジョブは、投入前に別の承認が要る。** `cv_synthetic_small`（公式に作成スクリプトも件数も無い）は**未解決のまま**維持する。検証分割は `dns_data_prep.sh` の sorted uttid の末尾 1/10（36,000 件、300 h）であり、これを `cv_synthetic_small` と呼ばない。**関係**: #31（TF-Locoformer の研究設定は VoiceBank 比較。チャンク 32,000）は研究側として残り、公式 DNS の再現は別 Dataset・別 Protocol になる。

## 実装済み

1. **評価の入力は DuckDB の名前付きセットだけ。Manifest は登録時にしか読まない。** 同じ名前なら入力・順序・混合条件が同じになり、Manifest や元ファイルの変更に評価が左右されない。
2. **`make db-init` と `make db-ingest` を分ける。`db-init` は `corpora.audio_files` に触れず、前後の指紋で確認する。** 評価セットの登録で、コーパス由来のテーブルを壊さない。
3. **合成混合は `rms_v1`。条件を case に保存して再生成する。** 区間全体の平均二乗電力の比で、VoiceBank-DEMAND・URGENT の手順でも、ITU-T P.56 でも、VAD でもない。seed は SHA-256 で作り（Python の `hash()` は使わない）、雑音の対応はセットの seed と path で決める（実験 seed では変わらない）。SE を変えても同じ入力で比べるため。
4. **WER は micro 集計と `wer-norm-v1`。出せない値は `na` と理由で残し、0 にしない。** 部分音声と全文の組は無効にする。不正な WER を作らないため。
5. **CHiME3 の正解は公式注釈の `prompt`。CH0・real・simu・`tr05_org` を clean 参照にしない。** 時間整合した clean 参照が無いのに PESQ / STOI を出さないため。
6. **SE と ASR は独立モジュール。評価は共通 API だけを呼ぶ。** ASR は使う系列のバックエンドだけを import し、環境も `.venvs/se` と分ける（NeMo の依存が合わない）。
6a. **プラットフォームはセットアップの入力だけにする。** 仮想環境は `.venvs/se`、`.venvs/asr`、`.venvs/official`、`.venvs/semambapp`、公式 `libdf` 用の `.venvs/deepfilternet` である。`tsubame` と `shinoda_lab` は環境名に入れない。旧称 lab と `.venvs/lab` は SHINODA-LAB を指していた。`make setup` は DB を初期化しない。依存の固定は `requirements/*.lock.txt`、公式ソースと重みは `requirements/official-assets.toml`。
7. **推論 API は推論専用。** `transcribe()` と `enhance()` に学習や勾配の経路を持たせない。
8. **独立 SE 実装は、公式コードに実行時依存しない。一致は最終波形の最大絶対誤差で判定する。** MP-SENet、TF-GridNet、DeepFilterNet3、MossFormerGAN、SEMamba++ は `docs/se/VALIDATION.md`。TF-Locoformer の `dns` は standalone separator と CPU で差 0、公開重みの GPU 波形差は 20 秒まで 2.24e-8 以下（`docs/training/TF_LOCOFORMER.md`）。
9. **ASR は、ASR 用に fine-tune されたチェックポイントを、そのデコーダのまま使う。** 自己教師ありだけのチェックポイントは拒否する。Parakeet は TDT / CTC / RNN-T をモデル ID のデコーダのまま使い、Whisper は `transcribe` だけにする。系列やデコーダの取り違えを防ぐため。
10. **結果は run 単位のディレクトリに JSON / JSONL で保存し、`results.jsonl` から再集計する。** 書き込みは原子的で、再開は成功レコードだけを再利用する。DuckDB への登録は、そのファイルを `register_run` で後から載せる。
11. **DB はレシピ JSON を管理し、音声生成は Python が解釈する。** 操作は順序付きの `additive_noise`、`rir`、`peak_normalize`（いずれも version 1）。未知の操作と version は拒否する。詳細は `docs/db/RECIPE.md`。
12. **`case_id` は正規化レシピの SHA-256 である。** キー順はソートし、浮動小数は小数 6 桁へ丸める。`case_id` 自身はハッシュに入れない。同じレシピは再構築しても同じ ID になる。
13. **登録データは `data/staging/` に保存してから DuckDB へ入れる。** 参照は `case_id` と `path` で持ち、rowid や採番に依存しない。同じステージングから作った DB は、登録順が違っても内容が一致する。
14. **旧 `eval.cases` の固定列を実行時に読まない。** 一度きりの変換は `src.data.migrate_legacy` で、ステージングと検証用 DB を作る。本番 `resource.duckdb` は、その検証のあとレシピスキーマへ置き換えた。旧ファイルは `data/db/backups/resource-legacy-20261031.duckdb` に残す。`migrate_legacy` は既存のステージングと再構築 DB を上書きしない。
15. **SE の学習は `src/training/` に置き、`enhance()` と `transcribe()` には入れない。** 最初のモデルは MP-SENet。Generator は推論実装をそのまま使い、損失と Metric Discriminator は学習側にある。公式ツリーは実行時に import しない。
16. **Global batch は厳密に保つ。** `micro_batch_size_per_gpu` は上限で、その範囲の最大の micro batch と整数の蓄積回数で global batch を作る。作れない構成はエラーにする。Global step は Optimizer 更新の回数である。MP-SENet の ExponentialLR は、公式と同じく、そのエポックの使える micro-batch を終えたときだけ進む。蓄積回数では進まない。DDP の all-reduce は forward 時に決まるので、`no_sync` は micro-batch の forward を包む。通常は最後の micro-batch だけ同期する。MP-SENet の公式損失と MossFormerGAN の Discriminator は遅延または複数 backward のため下記 32 の方法で同期する。SEMamba++ の損失は平均なので、micro-batch の backward は蓄積回数で割る。割らないと公式の batch 平均ではなく、micro-batch 勾配の総和になる。蓄積が 1 のときは Generator を 1 回だけ forward し、その波形を Discriminator と Generator の両方に使う。蓄積が 2 以上のときは全 micro-batch の計算グラフを保持しない。Generator に dropout は無いので、Discriminator を更新したあと micro-batch ごとに forward し直す。その forward は `accumulation_scope` の中で行い、遅延 backward の手動 all-reduce は使わない。参照の selective scan は学習時だけ再計算し、3 秒の逆伝播を 16 GB に収める。推論は再計算しない。
17. **学習の乱数は用途ごとに分ける。** 初期化、dropout、サンプル順、切り出しは独立である。切り出しと順序はサンプル ID と seed から再現し、消費順には依存させない。`deterministic: true` では決定的アルゴリズムを有効にし、決定的に計算できない CUDA 逆伝播は非決定的カーネルへ戻さず、同じ順伝播値の別実装にする。DeepFilterNet3 の spectral loss はそれ以外では公式の反射パディングを使う。決定的 CUDA の代替実装は勾配の加算順が変わり得るため、同一実装として扱わない。

   MP-SENet の STFT も CPU と通常の CUDA では公式の native centered reflection を使い、厳密な決定的 CUDA だけ明示反射にする。反射の実装が異なると、forward が一致しても backward の加算順が変わり、AdamW の更新が分岐するためである。
18. **学習データは名前付きセットのレシピだけを使う。** 教師が定義できないケースと、LibriSpeech test-clean・CHiME3 et05 を含む評価用セットは拒否する。ケースの識別はレシピハッシュで、採番 ID ではない。本番 `resource.duckdb` は評価セットの本番ファイルなので、学習からは名前で拒否する。
19. **SE の学習タスクは `src/training/se/` に分け、共通 Trainer に損失を書かない。** TF-Locoformer の `dns` は AdamW と `mr_l1_tfd`（時間重み 0.5、勾配クリップ 5）で、standalone separator との CPU 1 step の差は 0。 MP-SENet は公式ステップとの数値比較まで行った。AdamW 更新後の重み差は、初回ステップの閉形式で説明できる。TF-GridNet の学習損失は ESPnet の `mr_l1_tfd` である。SEMamba++ の参照ツリーはコピーしていない。Discriminator は公開仕様の multi-scale sub-band CQT（`nnAudio` の `CQT2010v2`）と 3 解像度 STFT を独立に実装している。参照コンストラクタが層へ渡していない幅 32 は使わず、実行される幅 128 に合わせる。MossFormerGAN の Discriminator は公開版由来の NISQA AdaptCNN、2 層 Conformer、attention pool と LearnableSigmoid を `src/training/se/mossformer_discriminator/` に持つ。DeepFilterNet3 の学習損失は出荷 `config.ini` の multi-resolution スペクトルと local SNR で、mask と SI-SDR は 0 である。`scheduler.name: deepfilter_cosine` のとき、YAML の `steps_per_epoch` と `epochs` で出荷の per-step cosine（warmup 3 epoch、学習率 1e-4 から 1e-3、下限 1e-6、weight decay は 1e-12 から 0.01）を Optimizer 更新の前に適用する。ステップ数はデータローダから推測しない。スモーク YAML は 8 ケース・batch 1 なので `steps_per_epoch: 8` である。
21. **標準コーパスは `src/data/corpora_catalog.py` の 14 件だけをリンクし、空の DB を `db-bootstrap` で作る。** DNS2020 と MS-SNSD は汎用索引で、初期カタログに含まれる。追加挿入の別経路は持たない。 VoiceBank-DEMAND の学習分割は公式 28 話者ファイルを話者単位で train 10,700 / validation 872（p286、p287）にし、公式 test 824 とは話者が重ならない。
20. **独立 SEMamba++ は参照 scan を既定とし、明示指定で外部 CUDA 融合演算を使う。** `scan_backend: fused` は CUDA 上で外部 `mamba-ssm` の `mamba_inner_fn` と Triton RMSNorm だけを使う。PyTorch 畳み込みのあと selective scan だけを融合する経路は、公式 fast path と backward がずれて学習が離れるので使わない。`mamba_inner_fn` の `xz` は公式と同じ非連続 stride `(time, batch * time, 1)` の view にし、contiguous コピーはしない。ネットワークと checkpoint キーは独立実装のまま保つ。CPU は reference に戻る。20 step の勾配スナップショットは公式の再実行でも反転し得る。学習の同等性はその再実行差と損失・重みで判断し、融合版の存在だけを長時間学習後の品質一致とみなさない。
23. **MossFormerGAN の AdamW は、公開 YAML の `weight_decay: 1e-5` ではなく、コンストラクタが渡さないときの PyTorch 既定 0.01 である。** 識別器の学習率は生成器の 2 倍。betas は (0.9, 0.999)、eps は 1e-8。検証に渡す値は時間領域 L1 ではなく、公式の生成器損失（0.1 * RI + 0.9 * magnitude + 0.2 * time + 0.05 * GAN）である。PESQ が計算できないバッチは 0 として分母に残し、Optimizer は進めない。識別器は検証中も train のままである。その検証損失が直前の記録より下がらない回が 5 回になると、最後に改善した checkpoint の重みと Optimizer を戻し、生成器の学習率だけを半分にする。その回数は半分にしたあとリセットしない。10 回で学習を止める。悪化した損失は記録上の最良値を上書きする。この回数と最良 snapshot は独立実装の checkpoint に残す。公開 Solver の再起動は `val_no_impv` と `best_val_loss` を初期値に戻す。
24. **H100 MIG 4g.47gb の SEMamba++ 本試験は micro 4 × 蓄積 2 である。** 3 秒・公式幅の micro 8 は 45.56 GiB を確保したあと discriminator で OOM した。長さ 8,000 の fused CUDA では batch 8 が載り、peak allocated は 9,610,847,232 バイトだった。同じ初期重みで batch 8 の自己再実行は音声最大差 0、generator 勾配の相対 L2 は 2.90e-4、更新後重みの相対 L2 は 1.39e-5 だった。micro 4 × 蓄積 2 は音声最大差 0.001338、generator 勾配の相対 L2 0.0282、重みの相対 L2 2.01e-4 で、自己再実行より大きい。勾配 norm は約 16.00 と 16.02 で、蓄積回数で割る縮尺は合っている。差は fused kernel の batch 形状に再現する。研究用本格学習はこの差を明示した micro 4 × 蓄積 2 で、`configs/training/semambapp_seed17.yaml` を使う。公式の 3 秒・1 forward の batch 8 とは別判定にする。MP-SENet の検証は全長を Generator に入れる。更新経路は iSTFT 長が入力長と違うとき拒否する。検証だけは公式の center iSTFT 長を許す。
25. **学習入力の先読みは、crop と順序の定義を変えない。** `data.load_workers`（既定 4）は発話の読み込みをスレッドで並べ、`data.prefetch`（既定 true）は次の Optimizer 更新分を GPU 更新と重ねる。切り出しとサンプル順は case id・seed・epoch の関数のままである。MP-SENet と MossFormerGAN の wideband PESQ は、行が 4 以上のとき spawn したプロセスで同じ `pesq` を行順のまま計算する。モデル、損失、batch、Optimizer、STFT、selective scan は変えていない。`torch.compile`、CUDA Graph、AMP、TF32 の変更は入れていない。
22. **SEMamba++ の GAN 更新は公式の系列順を使う。** 各サブ discriminator は real と fake を交互に処理し、CQT と multi-resolution の各損失を別に集計してから加算する。mel 損失と multi-resolution discriminator は公式の CPU 生成 Hann 窓を使い、mel basis は librosa の Slaney フィルタを使う。通常経路の反射パディングは公式に合わせ、厳密な決定的 CUDA では明示パディングを使う。処理順や項の結合を変えると浮動小数点の累算順が変わる。


26. **TF-GridNet の公式学習は ESPnet の可変チャンク iterator で、発話 RMS は掛けない。** `num_iters_per_epoch: 5000` は元発話数であり、optimizer 更新数ではない。1 epoch はその iterator が尽きるまでで、境界で検証、ReduceLROnPlateau、early stopping（patience 5、valid loss）、best 5（valid loss 最小と valid si_snr 最大）を進める。記録される si_snr は負の SI-SDR なので、max は SI-SDR が低い方を選ぶ。ピン留め ESPnet は `speech_volume_normalize` を None のままにする。公式モードの `configs/training/tf_gridnet_chunk_seed17.yaml` は `data.rms_normalize: false` である。他モデルと `tf_gridnet_fixed5000_seed17.yaml` は発話 RMS を維持し、固定 5,000 更新の checkpoint から公式ディレクトリへは再開しない。VoiceBank train 10,700 の実長では、seed 17 の epoch 1–5 の optimizer 更新数が 575、574、593、566、588 だった。短い発話の破棄と、batch 未満の端数チャンクの破棄を含む。複数 rank の chunk 計画は下記 37 の `espnet_chunk_v1` である。VoiceBank 上の単一プロセス更新数の測定は、その実装の前の記録である。詳細は [公式設定監査](../docs/training/OFFICIAL_TRAINING_AUDIT.md)。

27. **DeepFilterNet3 の公式学習は出荷 ini の batch schedule と 120 epoch である。** 実効 batch は `min(schedule, 64)`。128 と 9999 は 64 になる。cosine の表は loader 長が変わった epoch で作り直し、`epoch * steps + step` で引く。10,700 発話の 120 epoch は optimizer 更新 22,711 回で、`max_steps: 22711` がその回数である。次の更新は cosine 表の外を指す。早期停止は validation loss が 25 epoch 改善しないときで、改善するとカウンタを戻す。勾配蓄積で公式 batch を置き換えない。batch 32 と 64 はこの MIG に載る。研究用の検証は 1 発話ずつ計算した損失の非加重平均で、公式のパディング込み batch 平均とは別である。固定 VoiceBank レシピは公式のオンライン混合とは別である。設定は `configs/training/deepfilternet3_schedule_seed17.yaml`。

28. **長時間学習の管理経路は更新完了境界で保存し、前ジョブの成功を確認してから続ける。** `job_chain` は設定・source・commit・DB・環境と checkpoint の指紋を記録し、前状態と qacct の正常終了を要求する。保留数の上限を超える自動投入や、古い checkpoint への自動巻き戻しはしない。実装と対話 GPU スモークはあるが、qsub ジョブ間の動作は未検証であり本学習 GO ではない。検証範囲と残件は [ジョブ継続の検証](../docs/training/JOB_CONTINUATION_AUDIT.md)。
29. **研究室の本学習は、時間制限が無いホストではジョブを分割しない。** 定期 checkpoint と再開を使う。`SIGTERM` は現在の optimizer 更新を終えてから checkpoint を書き、`CHECKPOINTED` で戻る。data epoch 末に検証するタスク（MossFormerGAN）は、world size が 2 以上のとき全 rank が `SIGTERM` を受け、その更新境界で停止フラグを MAX で揃えてから同じ境界で止まる。`deadline` と `segment_steps` は world size 1 のままである。`SIGKILL` は書き込み中の一時ファイルを捨て、直前の完成 checkpoint を残す。同じ `checkpoint_dir` の二重起動は `.lock` で拒否する。完了時の `complete.json` がある実験は再開しない。破損した checkpoint は `TrainingError` にして再開元にしない。TSUBAME の `qsub` 連鎖はこの決定の対象外である。
31. **TF-Locoformer の研究設定は DNS レシピの学習手順と VoiceBank 比較を分けて書く。** `dns` のネットワーク、`mr_l1_tfd`、AdamW、勾配クリップ 5、ESPnet の `xavier_uniform`、4,000 step の線形 warmup のあとの ReduceLROnPlateau（factor 0.5、patience 3）は公式 DNS に合わせる。warmup は optimizer 更新のあとで、最初の更新だけ構築時の学習率を使う。warmup 中の validation も plateau の best、bad epoch、cooldown、last epoch を更新する。学習率は `initial_lr * (warmup_steps ** -1) * step_num` で、warmup 中に plateau が学習率を下げても次の warmup 更新がこの式で上書きする。研究の `valid.si_snr.best.pt` は SI-SDR（dB）を最大化する。公式 DNS の `best_model_criterion` は `valid/si_snr/max` だが、ピン留め ESPnet の `SISNRLoss` が stats に書くキーは `si_snr_loss` で、値は SI-SDR 損失である。`si_snr` キーは stats に無い。SI-SDR の最大化は公式 stats との一致ではない。学習ログの `si_sdr` は損失の側である。研究 YAML は `configs/training/tf_locoformer_voicebank.yaml` で、スモーク `configs/training/tf_locoformer.yaml` とは別名である。VoiceBank では 64,000 サンプルのチャンクが 10,700 件中 1,205 件しか残さないので、研究チャンクは 32,000 にする。発話 RMS は研究側で true、公式 DNS の `speech_volume_normalize` は null のまま別扱いである。不偏標準偏差が `1e-6` 未満の混合は学習で拒否し、推論は零を返す。検証の数値は `docs/training/TF_LOCOFORMER.md`。150 epoch の投入は、この決定だけでは始めない。
33. **公式再現の DB 基盤（P1）は `data/db/reproduction.duckdb` の `repro` スキーマである。** `resource.duckdb` とは別ファイルである。staging は `data/staging/reproduction/`、スナップショットは `data/db/snapshots/<dataset_id>/`。登録は 1 トランザクションで、同じ ID の同じ内容は何もしない。違う内容は拒否し、DB を変えない。再構築は新しいファイルで全表ハッシュが一致したときだけ残す。`selection_uses_test`、`claim_label` と profile、生成素材の検証済み shard は登録時に検査する。leakage 監査は、`resource.duckdb` を開かないとき、または `eval` が無いとき `UNKNOWN` であり `PASS` にしない。スナップショットは NumPy と JSON だけで読め、`.venvs/deepfilternet` は DuckDB を import しない。学習はこの DB ファイルを開かず、下記 35 の Pipeline がスナップショットを読む。DuckDB は asset の外部キーを COPY の途中で検査するため、親の `corpora` 素材を派生素材より先に挿入する。
36. **学習データの来歴（P4）は checkpoint ディレクトリの `data_provenance.json` が一次記録である。** `data_state` は再開位置であり、来歴 JSON は Dataset、snapshot、profile、`claim_label`、`selection_uses_test`、train / 選択集合の内容 SHA-256 と、stamp で確認できた派生元 SHA-256 を持つ。rank 0 だけが排他作成し、同じ run の再保存はファイルを書き換えない。評価は `src.evaluation.provenance` がこの JSON だけを読み、`src.reproduction` は import しない。`independent` は true / false / `UNKNOWN` で、`UNKNOWN` を独立評価にしない。ハッシュが一致したときだけ false にし、派生関係が足りないときは true にしない。`selection_uses_test` は独立性とは別に結果へ残す。来歴の無い checkpoint は `UNKNOWN`。`repro.runs` は学習後に `register_training_run` で載せる。学習中は開かない。同じ run の checkpoint 位置の更新と、別 run の挿入を区別し、dataset・snapshot・profile・claim が違う再登録は拒否する。表に列が無い claim と checkpoint パスは `data_state_json` に足す。実評価セットとの突合は未実装のままで `NOT_TESTED` である。現行の `resource.duckdb` には `eval` がある。Official Evaluation は [仕様](../docs/evaluation/OFFICIAL_EVALUATION.md) だけで未実装。

35. **固定ペアの学習 Pipeline（P3）はスナップショットを Trainer に渡す。** `src/reproduction/pipeline` が計画・読み込み・正規化・窓・バッチを行い、`src/training` は `TrainingData` だけを見る。学習は DuckDB を開かない。正規化・窓・順序は Dataset の protocol を使い、`cases.protocol_id` では判断しない。固定ペアに加え、MS-SNSD のオンデマンド再構築は下記 39 である。`data.pipeline: legacy`（またはキー無し）は従来の `RecipeDataset` 経路で、`src/training/data/legacy.py` が同じ順序・波形を `TrainingData` に包む。`pipeline: reproduction` は `data.dataset`（`name@version`）を必須にし、Legacy の `database` / `train_set` / `validation_set` / `rms_normalize` と併用すると拒否する。`selection_uses_test` と `data.allow_test_selection` の両方が無い公式 Dataset は開始前に拒否する。leakage-safe は test を validation に使わない。checkpoint の `data_state` は更新境界の epoch と `update_in_epoch`、snapshot hash、plan hash、world size、order policy を持つ。先読みは位置に数えない。`espnet_chunk_v1` は下記 37。`data.virtual_world_size` は chunk iterator の 1 プロセス計画にだけ使う。reproduction の固定ペアに付けると拒否する。公式の DataLoader worker 乱数列は再現しない。crop は `mix_seed("crop", seed, epoch, case_id)` の一様な開始位置である。詳細は [P3 検証](../docs/training/reproduction/P3_VERIFICATION.md)。

44. **学習の終了状態は `status.json` で区別し、公式完了だけが `complete.json` で再開を拒む。** `RUNNING` は開始時、`CHECKPOINTED` は期限・`segment_steps`・`SIGTERM` の更新境界、`INTERRUPTED` は公式予算より前の停止、`COMPLETED` は公式の終了、`FAILED` は例外である。`verification_max_updates` は `max_steps` 未満の検証用上限で、到達時は `interrupted.json` を書き、`complete.json` は書かない。同じディレクトリから、その上限を上げるか外して再開できる。管理されていない chunk iterator が `max_epochs` の前に `max_steps` へ達したときも `INTERRUPTED` である。期限または `segment_steps` の管理実行がそこで `max_steps` に達した場合は `TrainingError` になり、例外処理が `FAILED` を書く。`max_epochs`、early stop、plateau の停止、非 chunk の `max_steps` 到達は `COMPLETED` である。CLI の `--resume` は設定照合を行う。違ってよいのは `logging` だけである。`verification_max_updates` などの上限を外した本格設定への無警告の再開は拒否する。記録は [P10_B1_VERIFICATION](../docs/training/reproduction/P10_B1_VERIFICATION.md) と [P10-C preflight 修正](../docs/training/reproduction/preflight/P10_C_PREFLIGHT_FIX_VERIFICATION.md)。

32. **MP-SENet、DeepFilterNet3、MossFormerGAN の DDP は、遅延・二重 backward と未使用パラメータを明示的に扱う。** MP-SENet の公式損失は複数 micro-batch の Generator forward のあとに backward を遅延するため、DDP の自動同期を使わず、全 backward 後に Generator の勾配を rank 間平均する。 DeepFilterNet3 の `df_fc_a` は checkpoint に残るが forward では使わないため、DDP は未使用パラメータを検出する。MossFormerGAN の Discriminator は同じ micro-batch で 3 回 forward し、Generator と Discriminator の損失を別々に backward する。公式 DDP は両方を `find_unused_parameters=True`、`broadcast_buffers` 既定の True で包む。計測では True の 3 forward と 2 backward が終わるので、Discriminator も True にする。DDP が forward ごとにバッファを配るので、手動の追加 broadcast はしない。Generator の生きた BatchNorm は 0 なので、`convert_sync_batchnorm` を呼んでも SyncBatchNorm は増えない。SyncBatchNorm にするのは CUDA かつ world size が 2 以上のときだけである。CPU の複数 rank は BatchNorm のまま forward する。勾配は `no_sync` の forward のあと、その micro-batch の増分だけを rank 間平均し、走っている和を clip する。PyTorch 2.6 では、全 rank で同じ蓄積勾配をもう一度平均しても増分平均と同じ値になる。公式の 3 forward のあとの 2 回目の Discriminator backward は all-reduce されず、rank の重みが割れる。その割れはコピーせず、Discriminator 損失の増分も rank 間平均する。1 GPU の更新順、損失の割算、micro-batch ごとの clip は公式と同じである。world size 1 は通常の BatchNorm のままである。PESQ 欠測の micro-batch は backward せず、蓄積窓は後続の成功 micro-batch で埋める。`official_step` は失敗を含めて micro-batch ごとに増える。Trainer の `global_step` は Optimizer 更新の回数のままである。データ epoch の終わりでは、その更新回数が `validation_interval` で割り切れなくても検証し、その損失で plateau を更新する。2 GPU では、その micro-batch をいずれかの rank が落とすと全 rank が backward しない。片 rank だけの公式スキップは collective が割れるので採らない。検証は `rank_mod_fixed_v1` の epoch 0 で rank 分割する。公式 DistributedSampler は端数を捨ててから前方を繰り返すので、rank ごとのサンプル数は揃う。失敗 batch は分母に残り、損失 0 としては記録しない。Fix.1 の独立検証では、実音声 2 micro-batch の clip 前 norm が約 45 と 56 で、閾値 10 を超えた。頻度は 1 epoch では測っていない。検証件数が world size 未満のときは公式 sampler を呼ばず、参加する全 rank が同じ短い列を見る。824 件の rank 分割は変えない。1 件のスモークは公式 824 件分割ではない。

54. **Experiment Framework の Phase 3-D は、DeepFilterNet3 と SEMamba++ のオンライン供給を同じ `SnapshotDataModule` で行う。** `Dfn3IndexSampler` は `plan_online_epoch` を呼ぶ。`SampleRef.index` は sample index で、発話 index は `speech_key_positions` が描画時に決める。`group_size` は 1 で、違う値は `DataError`。world size 1 の短い最終 micro-batch は残す。`Dfn3Protocol` は `DFN3OnlineSpec.shipped()` と `render_mixture` を呼ぶ。教師は `official_mixed_target`。`OrderSampler` は SEMamba のとき `locate` を呼ばず、`rank_order` の全件を返す。端数の micro-batch と端数の蓄積群は `MicroBatcher` が捨て、`plan_semamba_epoch` と一致する。`SemambaProtocol` は `render_example` を呼ぶ。教師は `dry_clean`。実効 batch が出荷 batch と違うときは rank 0 が 1 行警告し、指定値を使う。kwargs の `global_batch` が積と違うときだけ `DataError` である。非整数の `sampling_factor` では、既存の `speech_key_positions` が検証 epoch でも発話キーを入れ替える。波形の種の epoch key は 0 のままである。検証波形の epoch 間一致は整数因子で測った。plan hash のトップレベルキーは足していない。固定ペアの `order_parameters` は `order_params` のままである。`OnlineDFN3TrainingData` と `OnlineSemambaTrainingData` は作らない。world size 2 の正式受け入れは実装済み 55。DeepFilterNet3 の学習接続は実装済み 63。SEMamba++ の学習は未実装である。記録は [Phase 3-D](../docs/training/experiment-framework/PHASE_3D_ONLINE.md)。

53. **Experiment Framework の Phase 3-C は、chunk を同じ `SnapshotDataModule` で供給する。** `ChunkSampler` は `plan_chunk_epoch` をプロセスの world size のまま呼ぶ。Trainer の epoch に 1 を足して ESPnet epoch にする。返った rank batch はすでに micro-batch なので、平坦化したあと `MicroBatcher` が同じ幅で区切り直す。`group_size` は 1 で、違う値は `DataError`。`global_batch` を省略したときは `micro_batch * world_size` を使い、書いたときはその積と一致しなければ `DataError`。検証は `valid.cases` を `shuffle=False`、`num_samples=None` で別計画にする。`ChunkProtocol` は algorithm が `pregenerated.ms_snsd_tfgridnet` なら `render_ms_snsd_pair`、`pregenerated.dns_tflocoformer` なら `render_dns_pair` を呼ぶ。PCM_16 のあとに span を切る。`OnDemandChunkData` と `DnsOnDemandChunkData` は作らない。旧 `_pair` は同じ公開関数を呼ぶ。波形の式は変えていない。`plan_hash` の形は Phase 3-B のままである。chunk 長、shift、cache、shuffle、`num_samples_per_epoch` は、その hash の `order_params` に足す。`order_params` 関数の固定ペア向けの戻りは変えていない。checkpoint 形式は `audio-db-experiment-v1` のままである。world size 2 の正式受け入れは実装済み 55。この決定の範囲では SE モデルは学習しない。TF-GridNet MS-SNSD の学習接続は実装済み 58。TF-Locoformer DNS の学習接続は実装済み 59。オンライン供給は下記 54。記録は [Phase 3-C](../docs/training/experiment-framework/PHASE_3C_CHUNK.md)。

52. **Experiment Framework の Phase 3-B は、固定ペアの `SnapshotDataModule` を `src/experiments/data/` に置く。** `src/experiments/data.py` はパッケージになり、`TensorPairData` の import パスは残る。Source、Sampler、Protocol、Batcher は `role: other` で、StateRegistry には入らない。DataModule だけが `role: data` である。数値は `rank_order`、`fixed_pair_crop`、`render_sample`、`validation_refs` を呼ぶ。`fixed_pair_crop` と長さ、pad、plan index の公開関数は `src/reproduction/pipeline/planner.py` の既存の式へ委譲し、式は変えていない。`ReproductionTrainingData` は作らない。学習は DuckDB を開かない。`identity()` は表示用の `dataset_name` と `dataset_version` を持つが、再開の一致判定はこれらを外す。`dataset_id` と `snapshot_hash` は外さない。`TensorPairData` の identity 比較は辞書全体のままである。DataModule の `close` は `Experiment.close()` だけが呼ぶ。構築が完成グラフの前に失敗したときも、Experiment が部分レジストリの data を閉じる。`StandardTrainer` は閉じない。forward の前に `inputs`、`targets`、`lengths` を `runtime.device` と違うときだけ移す。`group_size` を持つ DataModule は、Trainer の `accumulation` と違えば `RuntimeFailure` になる。`TensorPairData` にこの検査は付かない。checkpoint 形式は `audio-db-experiment-v1` のままである。合成 snapshot 上で、MP-SENet の `noisy_rms_unit_v1` と MossFormerGAN の `independent_audio_norm_v1` は、epoch 0 と 1、world size 1 で `plan_fixed_pair` と `render_sample` に対する波形の最大絶対誤差が 0 だった。これは公式 16 kHz 変換器との一致でも、本学習の完了でもない。prefetch の worker プールと world size 2 の正式受け入れは実装済み 55。記録は [Phase 3-B](../docs/training/experiment-framework/PHASE_3B_FIXED_PAIR.md)。

51. **Experiment Framework の Phase 2-C は、同じ公開 API で CUDA / FP32 と CUDA / AMP FP16 を、world size 1 と NCCL の world size 2 で学習し、再開する。** CUDA が使えない、rank と見える GPU が合わない、二つの rank が同じ GPU を選ぶ、backend が食い違う、CPU 上の AMP、`amp_bf16` は `PrepareError` で、CPU や FP32 や単一プロセスへ落とさない。プロセスにつき `torch.amp.GradScaler` は一つで、Trainer は `autocast`、`backward`、`clip`、`step`、`end_step` だけを呼ぶ。`GradScaler.step` は呼ばない。`applied` は `optimizer.step` を包んだ関数が呼ばれたときだけ True であり、SGD や Adam が `None` を返すことは skip ではない。非有限 loss は backward 前の `RuntimeFailure` である。有限 loss の勾配 overflow は、PyTorch 2.6.0 の private な `found_inf_per_device` を `all_reduce` MAX して全 rank で同じ 0 か 1 にし、溢れた step は全 rank が Optimizer と step ごとの Scheduler を進めない。logical step は進む。Scaler は `end_step` で 1 回だけ `update` する。形式は `audio-db-experiment-v1` のまま必須キーを足さない。`device` が無い runtime state は CPU と読む。AMP は Scaler 状態が欠けると復元しない。CUDA の UUID と index は `rng_by_rank` の各要素に入れ、違う GPU では RNG を戻さない。単一 GPU の DDP は Parameter を置き換えないので、resume は prepare と Optimizer 生成の後に unwrapped の `state_module` へ載せる。保存前の比較は runtime の GradScaler を含み、テンソルは CPU へ写してから集める。Optimizer state 全体の `all_gather_object` は本格 SE の方式にしない。2026-11-08 に A100、PyTorch `2.6.0+cu124`、CUDA 12.4、NCCL `(2, 21, 5)`、ドライバ `535.183.01` で、C1 から C4 の連続実行と中断再開の最大絶対誤差は 0 だった。FSDP、sharded checkpoint、BF16、複数 Optimizer の AMP 学習は未実装である。CPU / FP32 の MP-SENet 公式 GAN は実装済み 60 で、この 2-C の測定には含まない。記録は [Phase 2-C](../docs/training/experiment-framework/PHASE_2C_CUDA_AMP.md)。
